# Visualyrc Sketch — UI interaction specification

Status: review candidate, not implemented. User requirements are identified below;
numeric values and unresolved behavior are engineering recommendations.
This document supplements the drafts; it is not an artifact generated by the
Devpost Learn planning curriculum. Complete that curriculum before app coding.

## User requirements

- Browser app without login, profile avatars or author names.
- Canvas and the selected freeform Graph both use light oatmeal/purple mode.
- User explicitly requests no app implementation at this stage.
- Left-to-right structure: vertical waveform, sections, active-page Canvas, global Saezutter.
- Subtle grid and small numbers. Refined thin-line icons and small L-shaped resize grips.
- Text and Saezutter cards have square corners and flat surfaces; drop shadow only.
- Saezutter is a collapsible sidebar with text/image content-type icons; maximize Canvas area.
- Selection indicated by color, without a redundant vertical stripe.
- Magnetic hover highlight; local audio loading, playback controls and visible playhead.
- Canonical Node content shared across feed, Canvas and Graph. No code reuse from other Visualyrc apps.

## Layout and visual tokens — recommended

Desktop reference viewport 1700 × 1010. Proposed compact header 44px, transport 38px;
waveform 70px, section rail 100px, feed sidebar 260px; Canvas takes remaining width.
Provide explicit sidebar toggle; collapse to a 36px rail. Preserve composer draft
and scroll on collapse. Canvas expands without changing world coordinates or zoom.
On re-expansion preserve selected material visibility where feasible. Timeline rails
can collapse separately; no audio hides waveform/transport. These sizes are proposals.
At 1280px use 80px waveform, 120px sections and 280px feed. Below that width,
provide collapsible rails and a feed drawer; do not compress text indefinitely.
These widths require a runnable prototype for validation.

Background #FAFAF7; text #3A3B43; primary ink #0A0A0A;
accent #866490; secondary accent #93748A; selection tint #EDE6EF.
Keep normal text dark on light cards. Use white on the solid purple Post button;
verify actual contrast before finalizing tokens.

Use at most two fonts: readable sans-serif body, monospace for times/IDs.
Body 14–16px, supporting labels 11–12px. Grid 40 canvas units, low contrast,
never drawn over material contents. Hide fine grid when zoomed far out.
Icons 18px with consistent 1.25–1.5px strokes, minimum 36px desktop hit area.
Photo mounts retain the prior 3px radius proposal. Text and feed cards use
0px radius, solid flat fills and drop shadow only. No bevel, convex gradient,
inner shadow or upper-edge highlight. Selection changes fill only, without
adding a border or extra elevation. Apply the same text/feed treatment in Graph.

## Canvas manipulation — recommended

Click selects a Placement. Shift-click toggles multi-selection. Blank click clears.
Selection uses a pale fill or mount tint; no decorative selection frame.
A selected resizable item shows four small L-shaped corner controls, 8px visible
arms with 20px hit areas. Hover alone does not add four sets of grips across a board.
Keyboard focus has an independent visible focus indicator for accessibility.

Drag outside text-edit mode moves the Placement only. Double-click text edits
canonical Node content, updating every reference. Escape exits editing.
Corner drag resizes the local Placement; images retain aspect ratio by default.
Text resizing changes box dimensions and wrapping, never scales font size.
Recommended minimum box 120 × 64 canvas units; clamp without moving the opposite corner.
Provide numeric width/height controls as a keyboard alternative to dragging.
Use a separate remove-from-page command; it never deletes the Node.

Space + pointer drag pans when not editing. Wheel pans; explicit zoom controls
and modifier + wheel zoom around the pointer. Do not capture editing keystrokes.
Keep viewport and zoom per page. L grips remain constant screen size across zoom.

## Saezutter — recommended

Show newest first, content-type icon (T for text, outlined picture for image),
timestamp, body and overflow menu; omit profiles and social metrics. Icons identify
content, never identity. Image posts reference canonical image Nodes and display
a thumbnail; placing/editing follows the same shared-node rules as text.
The compact composer provides text entry and local image attachment; image-only
posts are valid. Decode/store failure retains draft and reports recovery.
Do not introduce mixed-content Node types solely for a caption in the first slice.
Separate cards with 12px gaps. Composer stays at panel bottom.
Use Ctrl/Cmd+Enter to post; Enter inserts newline. Reject whitespace-only posts.
Successful posting clears composer; failures retain draft and explain recovery.
Editing content preserves postedAt and updates canonical updatedAt.

Drag a card onto Canvas to create a new Placement of its existing Node.
Feed keeps its post. Drop position converts screen coordinates using current
Canvas transform. An Add to current page action provides the same operation
without drag. Repeated placements are allowed and independently movable.
Show a placement count in overflow/details, not repeated decorative badges.

## Magnetic hover — recommended prototype values

Apply to page/section selectors, mode switch and transport button backplates.
Maximum displacement 2px toward pointer; return about 140ms with restrained damping.
Labels, layout and hit targets stay fixed. Hover must not change persistent selection.
Disable during dragging, editing, touch input and prefers-reduced-motion.
Do not apply attraction to resize grips, waveform seeking or content cards.
Confirm feel in a runnable prototype; static images prove no motion behavior.

## Audio and sections — recommended minimum scope

One optional local audio asset per project; no upload or external service.
Use browser-supported WAV/MP3 as initial acceptance targets, not a universal codec promise.
Validate decoding before replacing current audio. On failure retain old audio and report error.
No autoplay on load. States: absent, loading, ready, playing, paused, ended, error.
Play starts/resumes; pause holds time; stop pauses and returns to 00:00.
At natural end remain at duration; next Play restarts at zero.
Space toggles playback only when focus is outside text fields and Canvas pan gesture.

Vertical time is linear: y = origin + timeSeconds × pixelsPerSecond.
Waveform, time ticks, section boundaries and playhead use the same transform
and shared vertical scroll. Playhead is horizontal across waveform/section rail;
it is a time indicator, independent of selected-state ornament rules.
Click waveform seeks; dragging playhead seeks continuously after pointer capture.
Playback position comes from the audio element clock, not accumulated animation deltas.
Render waveform peaks in time buckets; do not redraw/decode the full file every frame.

Use explicit Follow control, default off. Playback does not switch pages or scroll
Canvas automatically. Follow on keeps playhead visible in timeline only.
Selecting a section opens its independent canvas without seeking; a separate
Play from section action seeks to its start. No section editing by drag in the
initial slice; use start/end fields and an Add section action.

Each page has at most one optional [startMs,endMs) range for current audio.
Validate 0 ≤ start < end ≤ duration. Recommend nonoverlapping ranges with gaps allowed;
untimed pages remain valid and appear in a separate untimed group.
Without audio hide waveform/transport and show compact normal page navigation.
Replacing/removing audio preserves pages, Nodes and Placements; clearing or
retaining old range metadata requires an explicit review before confirmation.

Persist original audio Blob in IndexedDB, with asset ID/name/MIME/size/duration;
recreate/revoke object URLs at runtime. Never persist an object URL as the asset.
Cache waveform peaks separately, regeneratable from original. Save no playback
running state; reopen paused. Quota failures retain current session and offer backup.
Recommend a 50MiB per-audio-file product limit initially, subject to browser testing.
Recommend portable JSON backup including audio and images with an estimated-size
warning; base64 expands binary size. This needs import memory/quota validation.

## Model reconciliation before implementation

Keep Node kinds based on content (text/image initially); Saezutter is metadata,
not a separate saezuri kind. Placement owns x/y/width/height/z-order.
AudioAsset belongs to Project; Page.audioRange references audioAssetId.
Graph position is separate from Canvas Placement. Audio never creates graph edges
implicitly. Transactions preserve the already approved Node/Placement/Edge invariants.
The earlier spec.md unknown-content/saezuri placeholders must be replaced during
formal technical specification, not copied into production types.

## Acceptance checks

1. Post → place twice → edit text: feed and both placements update; layouts remain independent.
2. Resize image through each corner at multiple zooms; opposite corner and aspect ratio remain stable.
3. Keyboard user can post, place, resize, switch page and play/stop without pointer drag.
4. At known times, waveform tick, section boundary and playhead share the same y coordinate.
5. Seeking, pause, stop, natural end and switching page obey the stated clock behavior.
6. Reload restores content and audio but does not autoplay; backup restores assets in a fresh profile.
7. Removing placement/page/audio does not silently delete canonical Nodes.
8. Decode error, missing audio, storage quota and malformed import preserve recoverable work.
9. Reduced-motion disables magnetic displacement and keeps all controls understandable.

## Review needed

review are nonoverlapping time ranges, page selection without automatic seek,
Follow off by default, and the proposed 50MiB/portable-backup limits.
Do not mark these recommendations as user-approved or runtime-verified.

## Graph direction — freeform selected; other alternatives archived

The selected Graph uses the same canonical Node/Edge set, light surface, thin-line
icons, square flat text cards and color-only selection. Saezutter remains a global
collapsible sidebar; hide waveform/section rail in Graph to maximize workspace.
Audio playback state persists across view switches; a compact transport is
available through an explicit audio toggle, rather than silently stopping audio.
Graph positions persist separately; switching mode never rewrites placements.

- Open Constellation: free placement overview, sidebar collapsed; simplest initial
  selected visual baseline. Interaction details remain recommendations. All nodes, including isolated
  and unplaced nodes, remain visible/accessible.
- Page Atlas: optional page grouping. Canonical shared nodes appear once in a
  shared area with location metadata. Page membership never creates related edges.
  Unplaced nodes have their own region. More layout complexity; visual candidate only.
- Relation Lens: temporary selected-node focus with one-hop neighbors, explicit
  Back to all nodes and full-graph overview. Filtered nodes are hidden temporarily,
  never removed. Reuses the sidebar for Feed/Details rather than adding an inspector.

Graph connection uses explicit Link nodes action with source/target selection and
keyboard alternative; reject self-links and duplicate undirected related edges.
Node selection reveals placement locations; Open chooses a page and focuses that
placement. Unplaced nodes offer Add to current page. No image resize grips in Graph.
Saved content changes propagate across all modes; layout changes do not.

Additional acceptance checks: collapse/reopen sidebar retains draft and viewport;
image post → placement → reload preserves asset; Graph has one item per Node;
focus/grouping cannot delete or duplicate canonical Nodes. The user selected the freeform Graph. Advanced grouping/focus are unselected
and must not be introduced as submission requirements.

### Static image review limitations

Generated Graph concepts contain extra relation labels/arrows, selection borders
or underlines and occasional icon inconsistencies. These are not approved: initial
related edges are undirected, selection remains fill-only, and content icons must
match Node.kind. Canvas still visually overstates timeline rail widths; the compact
width targets above govern the prototype. Time/section alignment requires a shared
transform rather than tracing the generated pixels. Do not implement incidental
labels or controls from concept images as new requirements.

## Latest approval and implementation boundary

Canvas and freeform Graph layouts are selected, with BOTH in light mode.
Use light header/tool rails/cards/tray, dark text and neutral-grey connectors
stronger than the grid; selected fill is pale lavender. Preserve an isolated Node
and one rendered item per canonical Node. No dark-theme switch is required.
Image selection does not approve generated semantic edge labels or selection
stripes. This remains design/specification work only; app implementation is
explicitly on hold at the user's instruction. No curriculum completion is implied.
