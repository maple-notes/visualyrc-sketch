# Visualyrc Sketch

A spatial workspace for ideas, references, and creative planning.

Review note: drafted through the installed 2-scope instructions from the user's
existing answers. Later PRD/spec drafts were requested together; all three were subsequently approved by the user.

## The Unique Kernel
One piece of information can remain in the chronological Saezutter feed, appear
on multiple independent canvases, and participate in a project-wide Graph.
Editing its content updates every reference; moving a placement changes only it.

## Who It's For
Solo creators collecting references and planning videos, songs, stories or designs.
They need to turn unstructured thoughts into visual arrangements without losing
chronology or relationships across pages. This is a single-user local workspace.

## The Core Loop
Capture text or an image → place a reference on a page → arrange it → connect it
to another idea across pages → return through Graph → edit and revisit later.
Optional local audio gives pages time ranges without making audio mandatory.

## Inspiration & Identity
The user selected the light Canvas and freeform Graph references preserved under
`outputs/design-selected/`. Both modes use oatmeal, charcoal and muted purple.
Thin-line icons, small L-shaped resize grips, a faint grid and small numbers.
Text/feed cards are square, flat and shadowed. Saezutter is a collapsible sidebar.
Arknights/Endfield and Teenage Engineering inspire instrument-like precision;
never copy their assets. Local AIR_MOUS palette guides color.
No external reference research was performed for this drafting pass.

## Why This Matters to the Learner
The learner wants to understand web-app performance improvement, code
optimization and the process of releasing a real product. Tie these goals to
actual measurements and release checks; do not add features as learning exercises.

## What "Working" Looks Like
A reviewer sees a note captured, placed on two pages, edited everywhere, related
to an image, and reached again from Graph. Reload and portable project restore
preserve the result. With optional audio, playback and a vertical playhead work
and timed sections open their own canvases. The same app works without audio.

## The POC Boundary
Candidate submission scope, derived from requested capabilities:
- One active local project; create/open, text/image content and page management.
- Saezutter capture/edit, reference placement, independent canvas pan/zoom/resize.
- Freeform Graph of all canonical Nodes, explicit related edges, page navigation.
- Browser autosave and portable `.vsketch` backup/restore including original media.
- One optional local audio source, play/pause/stop/seek, waveform, timed pages.
- Selected light UI, content-type icons, collapsible sidebar and modest magnetic hover.
- Accessible alternatives to drag operations and recoverable errors.
This exceeds the curriculum's small 2–4-hour exercise; that figure is not a build
estimate. Prove the shared-content loop early. Audio, binary backup and gesture
handling are material risks; do not silently cut them if delivery becomes difficult.

## Later
URL cards, external embeds, drawing, elaborate mode-transition animation, advanced
Graph grouping/focus, broad codec/device support and multiple-project management.

## Explicitly Cut
Accounts/cloud sync/collaboration: unnecessary for local solo use.
AI generation or semantic linking: does not prove the requested reference model.
Electron, existing Visualyrc product code and external paid APIs: outside the boundary.
Native OS file association and automatic overwrite of downloaded files: not needed
for browser-based project import/export.

## Review Outcome
The user approved the full optional audio slice and portable binary backup as
submission scope. Build the shared-content kernel first. Runtime checks and
release decisions remain explicit; approval does not start app implementation.
