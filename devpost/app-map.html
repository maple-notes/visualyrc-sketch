One idea, several places.

Saezutter, page canvases and Graph refer to one canonical content record. Each placement owns its own geometry. The browser saves the project and original media locally; a portable .vsketch file transfers them together.

This is an offline reference route prepared from the working code. The learner has not yet completed an interactive code tour or final product review.

1 · Post an ideasrc/app.tsx

The composer calls run with postText. The shell immediately shows the shared idea and marks it Saving.

2 · Keep one content recordsrc/domain/model.ts

postText creates a Node and Post metadata. place adds a reference. validateProject rejects broken links.

3 · Commit before Savedsrc/storage/db.ts

saveProject commits the project and media together. The UI says Saved only after success. Failure keeps dirty content for retry or export.

Follow the reference route

  1. Open src/app.tsx and search for className="composer", then const run. These are the visible action and shared save queue.
  2. Open src/domain/model.ts and search for postText, place and removeContent. Notice how removing a placement differs from deleting shared content.
  3. Open src/storage/db.ts and search for saveProject. The transaction writes the document and original assets, then reclaims only unreferenced media.

To change this, start here

Colors, shadows, spacing and the sidebar

src/styles/app.css owns the light palette and layout. Text/feed cards stay square and flat. Selection fill is separate from keyboard focus.

Canvas movement, L grips and Graph rendering

src/views/Board.tsx uses Placement IDs in Canvas and Node IDs in Graph. Final pointer and keyboard movements update canonical geometry. Editing text never clones content.

Graph links come from onConnect in the same file (drag from one card's handle to another's) or from the Link action in src/app.tsx. Graph card sizes are saved with the Graph position (graph[].width and height in model.ts); GRAPH_TEXT_CAP in Board.tsx and the --graph-cap rule in app.css stop a long note from growing its card forever.

Audio and the vertical playhead

src/audio/Timeline.tsx: useAudio observes the committed media asset and owns one audio element. The timeline uses one seconds-to-pixels transform for waveform, ranges and playhead. waveform.worker.ts creates bounded peaks.

Portable backup and validation

src/storage/archive.ts: exportArchive, readEntries and importArchive. The reader checks directory consistency, CRC, schemas, references and actual expanded bytes. Import remaps IDs into a new project.

A practice to reuse

Specify a visible result before asking an agent to implement it. “Resize only this placement; editing text updates both pages; reload preserves both” became domain tests plus actual browser gestures. A successful build alone would not have detected the audio replacement race; exercising replacement did.

For optimization, compare the same source and change one thing. work/measure-bundle.mjs compares eager versus deferred archive loading. The measured initial gzip reduction is 7,962 bytes. This measures payload bytes, not frames per second or network load time.

Feed an awkward input and write down a number. A 30,000-character note made a Graph card 25,189 px tall once cards grew with their text. Capping the growth at 460 px brought the tallest card to 428 px in the same test. A pass over odd inputs found it; the unit tests and the happy-path recording had not.
